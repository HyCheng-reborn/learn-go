# 02 - Slice：len、cap、append 与底层数组

这是你之前重点观察过的例子。

```go
a := make([]int, 3)
a[0], a[1], a[2] = 10, 20, 30
b := a

a = append(a, 40)
a[0] = 999
```

## append 前

`a` 和 `b` 的 slice header 是两份值，但它们指向同一个底层数组：

```text
a ──┐
    ├──> [10 20 30]
b ──┘
```

## 为什么 append 后 b 可能没有变成 999

初始：

```go
make([]int, 3)
```

通常得到：

```text
len = 3
cap = 3
```

这时再 append 一个元素没有容量可用，Go 需要申请新的底层数组：

```text
旧：b ─────> [10 20 30]

新：a ─────> [10 20 30 40]
```

所以之后：

```go
a[0] = 999
```

改的是新数组，`b` 仍看到旧数组。

## 非常重要

不要把“cap 一定从 3 变成 6”当成语言规范。

具体扩容容量属于运行时实现细节；真正应该掌握的是：

> append 超过当前容量时，可能分配新底层数组，因此原本共享数据的 slice 会从那一刻开始脱钩。

## Python 对照

Python `list` 和 Go `slice` 虽然都能动态增长，但底层语义不是一回事。Go slice 还显式暴露 `len` 和 `cap`，并且共享底层数组是理解很多 bug 的关键。
